`buildPointsSeries` in `src/domain/index-builder.ts` gains a `canonicalPlayerId` argument and maps each entry's `id` through it, as `normalizeResult` already does for team members ([Player alias resolution](/features/player-identity.md), [Rankings, ratings and snapshots](/features/rankings-and-ratings.md)). Both callers pass the map: `buildIndex` and the snapshot route in `src/routes/snapshots.ts` (`index.canonicalPlayerId`). If two upstream entries in one series resolve to the same canonical player, both are kept (degrade and flag, [/conventions/degrade-and-flag.md](/conventions/degrade-and-flag.md)) and a warning is emitted; the profile shows the first match.
